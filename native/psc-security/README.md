# Windows protected state helper (source review candidate)

This helper is separate from the cd7 host enrollment helper. Its only authority is the fixed JSON stdin protocol in protocol.go: protected state preflight/read/write/remove/exists, executable custody checks and identity-file custody checks. There is no shell, SSH executor, network client or arbitrary filename operation. Credentials enter and leave through private pipes; diagnostics are generic. DPAPI uses the current Windows user with UI forbidden, never machine-wide protection.

State directories and files must have a current-user owner and a protected explicit DACL granting only that user and SYSTEM. Newly created objects receive that descriptor at creation. Existing unsafe objects are refused without modifying their permissions. Ancestors must have trusted ownership and no unsafe grants to other principals. Every ancestor is opened without delete sharing and held throughout the operation; reparse points, non-disk files and multi-linked files are refused. A private exclusive lock serializes state operations. Installation must preserve the same protected custody for this helper itself before any secret request is read.

Writes create an exclusive protected temporary file in the verified directory, flush it, publish with MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH), then reopen, validate, flush and compare the published contents. Credentials are encrypted before the temporary file is created. These checks establish checked publication and file flush under the local Windows filesystem semantics. They do not assert POSIX directory-fsync equivalence, a universal power-loss guarantee, isolation against the same user or an administrator, or native runtime acceptance based on Linux tests.

The module is locked to Go 1.27.2 and golang.org/x/sys v0.48.0 with exact go.sum entries. Linux protocol/policy tests exercise the actual policy called by the Windows adapter. GOOS=windows go vet checks the adapter's types and APIs without executing a Windows executable. Building, protected staging and native qualification require the parent's later source/artifact acceptance.
